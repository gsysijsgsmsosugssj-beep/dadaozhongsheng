# Safari 上登电报网页版一直转圈：跨站跟踪拦掉的 4 个环节，逐条放行就能进

上周三下午在咖啡馆，我把 MacBook 摊开准备回几条积压的消息。Safari 打开网页版，二维码那块区域先是白了一瞬，然后中间开始转圈——就是那种一小圈灰色弧线，转得不快不慢，一副"我在努力"的样子。我等了四十多秒，圈还在转，手机那头自然什么也没收到。同一台机器、同一条 WiFi、同一个账号，我换到 Chrome 试了一次，十五秒进到聊天列表。

差别只在浏览器。那台机器上 Safari 的「阻止跨网站跟踪」是开着的，而网页版的登录流程里有好几段请求要跨域取资源、跨域回调状态，被这套机制当成跟踪器拦掉之后，界面上不会报错，只会转圈。设置项叫法、路径层级在 [Safari 浏览器使用建议](https://tlgrbt-web.com) 那节列得比我全，这篇只写我自己量到的现象和改法。

## 一、先分清两种转圈：页面没出来，还是确认没回来

这两种在屏幕上长得几乎一样，处理顺序却相反。

**骨架都没出来**：二维码区域的边框、说明文字、扫一扫提示全空着，只有一个加载指示器在动。这类是图片、脚本、样式被拦，页面根本没渲染完。

**页面完整，扫完卡住**：二维码清清楚楚，手机扫了，页面停在"等待确认"，手机端却弹不出确认卡片，或者弹了点了没反应。这类是扫码之后的轮询请求被拦——请求发不出去，前端就一直等一个永远不来的答复。

判断办法很省事：Safari 菜单栏「文件 → 新建无痕窗口」（`Command + Shift + N`），把地址重敲一遍。无痕里能进，说明是扩展或站点数据在捣鬼；无痕照样转圈，而换 Chrome 能进，基本可以锁定到跨站跟踪这一层。

## 二、设置路径：Mac 一个入口，iPhone 两个入口

同一个开关，桌面上藏在 Safari 自己的设置里，手机上藏在系统设置里，而且系统版本不同位置还不一样。

| 平台 | 完整路径 | 容易走错的点 |
| --- | --- | --- |
| **macOS（Safari 17 及以上）** | Safari 菜单 → 设置 → 隐私 → 「阻止跨网站跟踪」 | 菜单名是"设置"不是"偏好设置"，老教程还写着偏好设置 |
| **macOS（Safari 26 系）** | 同上，隐私页多出「隐藏 IP 地址」，可选"对跟踪器"或"对所有网站" | 选成"对所有网站"时首屏会更慢，慢到像加载失败 |
| **iOS 18 / iPadOS 18** | 设置 → App → Safari → 隐私与安全 | Safari 被挪进了「App」分组，不在设置首页那一列 |
| **iOS 17 及更早** | 设置 → Safari → 隐私与安全 | 路径短一层，升级系统后按老路径反而找不到 |

新版里那个「隐藏 IP 地址」是很多人忽略的一条。它的作用是把请求先绕去中继再出来，首屏资源一多，等待时间会被拉长；网络本身不稳的时候，表现出来就是加载到一半停住、页面超时重载，然后你以为是站点挂了。

## 三、影响对照：拦掉哪一段，登录就坏成哪一种

我把自己遇过、以及同事反馈过的现象对着设置项排了一遍，发现症状和原因是能一一对上号的。

| 被拦的部分 | 屏幕上看到什么 | 通常被误判成 |
| --- | --- | --- |
| 二维码区域的图片与脚本资源 | 二维码区空白，或一直转圈不结束 | 网络慢、网站挂了 |
| 扫码后的状态轮询请求 | 卡在"等待确认"，手机端没弹窗 | 手机没联网、App 被杀 |
| 第三方 Cookie 与本地存储 | 登录成功，过几天打开又变登录页 | 账号异常、被人顶掉 |
| 跨站跳转带回的状态参数 | 从群里点链接进来，落地就是登录页 | 链接失效、对方发错 |
| 隐藏 IP 的中继链路 | 页面加载到一半停住，提示重载 | 带宽不够、节点不稳 |

看懂这张表的用处在于：**只要现象落在右列任意一行，就别再从网络和账号那边找原因**，先去把跨站跟踪那一项对本站点放行。

## 四、站点级放行：五步，只开这一个口子

全局关掉「阻止跨网站跟踪」，等于把日常浏览的隐私保护一起拆了，代价远比省下的那两分钟大。正确做法是只给这一个站点开口子。

1. 在已打开的网页版页面，点地址栏左侧的「页面设置」图标（锁形或字母标）；
2. 弹出面板里找到「减少隐私保护」，或旧版写的「允许跨站跟踪」；
3. 勾上，只作用于当前这个域名；
4. 按 `Command + R` 重新载入，看二维码是否一次渲染出来；
5. 还不行就把标签页关掉，重新敲地址进，别在原地反复刷新。

有个细节要留意：**Safari 的放行是按域名逐条记的**。`tlgrbt-web.com` 和带前缀的子域在你这里是两条独立记录，换一个入口进去，等于从头再问一遍。所以认准一个入口，把它加进收藏夹，以后都从那儿进。

## 五、七天失效：反复重扫不一定是号出问题

有一阵我很纳闷：明明勾了保持登录，周一扫的码，下周一打开又是登录页。后来才明白，这是跨站跟踪机制的连带效果——它对脚本可写的那部分站点存储设了时限，到期就清。Safari 16.4 之后这条策略执行得更明显，表现就是"登录能成，但留不住"。

这件事改变的是使用习惯，不是账号本身。我现在把网页版当**临时设备**用：手机端始终在线，电脑上要用就扫一次码，十几秒的事；需要常驻的场景老老实实用桌面客户端。会话、退出、共享电脑这几种情况怎么处理，[Cookie 与登录状态说明](https://tlgrbt-web.com) 里分得比我这节细，值得顺手看一眼。

## 六、从群里点链接进来，落地就是未登录页

群里有人丢来一个会话链接，你点开，跳过去的却是登录页——很多人以为链接坏了。跨站请求被拦之后，跳转带过去的状态参数会被裁掉，目标页面拿不到上下文，只能把你丢回入口。这不是链接的问题，也不是权限的问题。

我现在的做法是先开一个已经登录的标签页，再把链接复制到那个标签的地址栏里粘贴回车。同一标签内跳转，上下文还在，直接就落在对应的会话上。

## 七、用对照组代替瞎试

改设置之前，先花两分钟做两组对照，比在设置里翻半小时有效。

- **同一账号、同一网络、换浏览器**：Chrome 能进、Safari 转圈 → 问题在本机浏览器设置；
- **同一浏览器、换一个网络**：家里不行、手机热点能进 → 问题在出口链路，不在隐私设置；
- **同一浏览器、换一个入口地址**：A 入口不行、B 入口能进 → 那个域名的放行记录没生效。

## 八、最小排查顺序

1. 无痕窗口试一次，先排除扩展；
2. 关掉广告拦截、脚本管理类扩展再试，它们最容易把网页版依赖的请求当广告处理；
3. 对本站点放行跨站跟踪，刷新；
4. 清掉这个站点的网站数据（会话会一起清掉，需要重扫，事先想清楚），只清记录、不动 Cookie 的先后顺序见 [浏览器缓存清理指南](https://tlgrbt-web.com)；
5. 上面四条都干净还不正常，再去动网络和节点。

顺序别颠倒。我见过太多人一上来就换节点，换了六个还是转圈，其实开关一直没动过。

## 把口子开在这一个站点上

回到咖啡馆那台机器。我给这个站点单独放行之后，二维码是立刻就出来的——不是变快了一点，是那种"原来它一直能加载，只是被按住"的感觉。同一台机器、同一条网络，前后差别只在一个勾选框。

这套默认值值得留着。日常浏览时它替你挡掉的东西，比它给网页版添的麻烦多得多；需要为某一个站点开一道口子的时候，就精确地开那一道，别顺手把整层保护拆掉。真正省时间的不是找到那个开关，是知道**它只会以"转圈""卡在等待确认""隔几天又要重扫"这几种样子出现**——下次再碰上，你直接就能对上号。

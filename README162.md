# 清掉一个站却退出全部账号：Firefox 缓存与站点数据的 4 层清理粒度对照（含只清 Telegram 网页版、保住登录态的做法）

上周三下午，我在一台旧笔记本上开网页版电报，群头像全成了灰色方块，往上翻历史卡住不动。判断是缓存坏了，就在 Firefox 设置里勾上"Cookie 和网站数据"加"临时缓存的网页内容"，回车确定，刷新后电报确实好了。

问题是同一台机器上另外七个站的登录全没了：公司 OA、两个邮箱、后台管理系统，还有一个我正填到一半的工单页面。四十分钟里重登了七次，其中一个还要翻手机找验证码，找到时已经过期。那天我才认真去看这几个按钮各管多宽——它们不是一个开关的强弱版本，而是**四种完全不同颗粒度的操作**，长得像、位置近、后果差着量级。

下文的分层我拿 [浏览器缓存清理指南](https://tlgrgs-web.com) 里那套排查路径对着核过一遍，补上自己踩出来的坑。

## 一、"只清一个站"在 Firefox 里能不能做到

能做到，但只对一半数据成立。

Cookie、本地存储（localStorage）、IndexedDB、缓存存储（Cache Storage）、Service Worker 注册信息，这些都挂在域名下面，可以按域名删。HTTP 缓存不是——它按文件落盘，Firefox 没给"只删某一个站的缓存文件"这个按钮，只能按时间范围整库清，或者靠强制刷新让那页重取资源。

这就是误清的根源：**同一个"清除数据"入口里混着两种颗粒度的东西**，一个受站点边界约束，一个不受。你以为在缩小范围，其实只缩小了一半。

## 二、四层粒度对照

| 层级 | 入口 | 作用范围 | 电报网页版的直接后果 | 该在什么时候用 |
| --- | --- | --- | --- | --- |
| L1 全库 · 全类型 · 全时间 | `Ctrl + Shift + Delete`，时间范围选"全部历史"，Cookie 与缓存都勾 | 整个配置文件，所有站点 | 全部站点掉登录，逐个重登 | 换机前、怀疑配置损坏 |
| L2 全库 · 单类型 · 按时间 | 同一对话框，只勾"临时缓存的网页内容"，范围选"最近一小时"或"今天" | 所有站点的缓存文件，不碰 Cookie | 不用重扫码，只重下资源 | 白屏、样式错乱、按钮点不动 |
| L3 单站点 · 全部数据 | 设置 → 隐私与安全 → Cookie 和网站数据 → **管理数据…** → 搜域名 → 整行选中 → **保存更改** | 一个域名下的 Cookie + 本地存储 + IndexedDB | 需要重新扫码登录 | 只有这一个站出问题 |
| L4 单站点 · 单项 | 开发者工具（F12）→「存储」→ 左侧站点树 → 在单项上右键删除 | 某条 Cookie、某个 IndexedDB 库、某个 Service Worker | 视删哪项而定，多数能保住登录 | 精修、定位到底是哪一项坏 |

绝大多数人栽在 L1 和 L3 之间：想的是 L3，手点的是 L1。

## 三、最容易错位的三件事

**第一件：「管理数据…」里没有缓存。** 那个列表只有"网站 / 大小 / 上次修改时间"三列，装的是 Cookie 和站点数据；在这儿清得再干净，缓存该多大还是多大。要动缓存只能走 L2 或强制刷新。

**第二件：「保存更改」不是即时生效。** 对话框一关，已经打开的标签页里数据还在内存里跑。我清完没刷新，看页面照旧，以为没生效又清一遍，第二遍手滑把本地存储带走，登录没了。改完必须 F5。

**第三件：清掉 Cookie 不等于退出登录。** 网页版的会话标识不止存在 Cookie 里，本地存储也留了一份。只删 Cookie 刷新，往往还是已登录；反过来只删本地存储，Cookie 里的那半截也在。真想干净退出，用站内菜单的"退出登录"，比清数据靠谱。这块机制在 [Cookie 与登录状态说明](https://tlgrgs-web.com) 里讲得更细。

## 四、只清 Telegram 网页版那一份的正确顺序

前提：只有这一个站异常，别的站正常。按顺序走，别跳步。

1. **先确认域名。** 地址栏里核对和你要清的是同一个。同一站点常有 `web.`、`m.` 之类子域前缀，存储上是分开的条目，清错等于白清。
2. **强制刷新试一次。** `Ctrl + Shift + R`，绕过缓存重取资源，不改动任何存储。能恢复就不用往下走。
3. **关掉这个站的所有标签页。** 包括后台挂着的那个，页面开着会把存储写回去，清完又被补上。
4. **设置 → 隐私与安全 → "Cookie 和网站数据" → 点「管理数据…」。** 顶部搜索框输入域名关键字，列表收窄到一两行。
5. **展开那一行看子项。** 只想修显示问题，就先只取消缓存存储、IndexedDB 那几条，Cookie 留着不动，再按「保存更改」。
6. **回标签页按 F5 验收。** 仍是未登录，说明会话本身坏了，重复第 4 步，这次整行选中后按「移除全部」，再「保存更改」。
7. **要连缓存一起清，走 L2。** `Ctrl + Shift + Delete` → 范围选"今天" → 只勾"临时缓存的网页内容" → 确定。这一步不影响任何站点的登录状态。
8. **要更细就上开发者工具。** F12 →「存储」→ 左侧选该域名 → 在「Cookie」「本地存储」「IndexedDB」「缓存存储」「Service Workers」上分别右键删除。删完回「Service Workers」确认旧的那条状态变成"已注销"，否则页面仍被旧脚本接管，清完照样老样子。

## 五、清完怎么反查清到了哪一层

不用回忆点了什么，看现象倒推：

- 样式恢复、头像重新加载、**没让你扫码** → 只动到缓存，属于 L2 或 L4 的缓存存储。
- 要求重新扫码 → Cookie 或本地存储被清，走到了 L3。
- 语言回退成英文、主题变浅色、草稿没了，**但仍是登录状态** → 本地存储被清，另一份令牌还在。
- 每次刷新都要重扫，页面还甩一句让你允许本站使用本地存储的提示 → 这个站被设成了"阻止"，去同区块的「管理例外…」删掉那条。

顺带说个版本差异：早几年的 Firefox 把 Cookie 分成"接受来自网站的 Cookie"和"接受第三方 Cookie"两个独立勾选，例外列表就摆在旁边；后来收成一个总开关，例外挪进「管理例外…」按钮。老教程按旧界面写路径，在新版上找不到"第三方 Cookie"那一行，别以为是装错了版本。

## 六、把粒度变成习惯

那次之后我改了几个固定动作，再没整批掉过登录。

`Ctrl + Shift + Delete` 的时间范围常年停在"今天"，不留给"全部历史"，误清概率砍掉大半。要长期保住登录的站点，加进「管理例外…」的允许列表，别的清理动作就不会顺手带走它。工作号和私人号分开放进容器标签，出问题时只清容器里那份。换机器之前在站内正常退出，而不是关机了事、回头靠清数据收拾。

想从界面、权限、缓存到登录态按顺序过一遍，[Telegram 网页版中文使用指南](https://tlgrgs-web.com) 是按小节拆开的，卡在哪一步就看哪一节。

清数据难的不是点按钮，是点之前知道自己要删掉多大一块。粒度选对了，一次 F5 能解决的问题，不会变成七个站重新登录。
